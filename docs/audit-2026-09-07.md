# Profile isolation and application quality audit

This audit covered the current native application, provider launch contracts,
profile persistence and recovery, process attribution, account usage, local
chat indexing, asynchronous selection, and primary interface flows. Changes
were made in an isolated worktree so unrelated checkout files were preserved.
Existing account files were not manually modified or migrated, and no account
data was copied into this repository.

AgentDock provides application-state separation. It cannot guarantee absolute
isolation between processes running as the same macOS user. Files, network,
Keychain, developer credentials, ordinary environment variables, and shell
startup configuration remain shared resources. Separate operating-system
accounts or virtual machines are required when those are part of the boundary.

## Findings and implemented changes

| Priority | Finding | Change and evidence |
| --- | --- | --- |
| High | A restored Codex profile could claim the Claude provider directory, including nested profiles. Recovery journals could also target provider namespaces or another profile's shortcut. | Reject namespace roots, conflicting ownership, duplicate shortcuts, and non-app shortcut names. Real filesystem regressions reproduced the restore defect before the fix. |
| High | Codex's inherited Electron data path could select a different profile; omitting that path also prevented the installed app from preserving the selected home through shell startup. | Pin the selected Electron path and home together. Clear inherited profile/server/runtime selectors in shared launch code, also used by shortcuts. |
| High | Claude received the selected environment path but still opened browser state under the default data root. A returned process was not sufficient proof of profile ownership. | Pair the verified environment contract with the matching Chromium user-data argument. Reject reused launch PIDs and never stop an unverified instance. The original live failure reproduced, and the corrected two-profile restart check passed while preserving existing instances. |
| High | Ambiguous process arguments and bundle-prefix lookalikes could associate one process with another profile. | Require unambiguous profile roots, exact argument boundaries, and a bundle directory boundary. Parser regressions reproduced the original failures. Existing signature and live PID checks remain in place. |
| High | Symlink aliases could acquire separate locks for the same profile, and lock files followed symlinks. | Derive locks from canonical profile paths; open without following links; require a regular, singly linked file owned by the current user. Both failures were reproduced with real filesystem locks. |
| High | Native quota reads inherited credentials/account routing; malformed custom-provider selectors could silently select OpenAI. | Native reads remove account/endpoint overrides and pin the selected home. Unsafe or unsupported provider configuration reports unavailable. Explicit custom-provider authentication remains supported. |
| High | A provider child could exit during protocol writes and deliver `SIGPIPE` to the parent application. A later real-service test run exited with signal 13. | Suppress that signal on the individual stdin pipe, so the write throws `EPIPE` through the existing error path. A real exited-process regression verifies descriptor policy and failed writes without changing process-wide signal handling. |
| High | Claude Desktop usage could skip account verification when its account field was missing, and an identity mismatch could retain cached usage. | Require valid Desktop account and organization IDs, evict mismatched cache entries, and enforce cookie database containment/symlink checks. |
| Medium | A managed chat index was keyed by profile ID without binding the underlying source root. Duplicate cached paths could trap dictionary construction. | Bind indexes to their source root and reject duplicate paths before reuse. |
| Medium | Direct selection changes could retain another profile's transcript; invalid profile selections fell back to the first profile. | Immediately cancel and clear chat state on every selection change. Unknown selections resolve to no profile. Regression uses two real profiles with the same provider session ID. |
| Medium | Warm transcript loads could report a changed conversation solely because cached timestamps lost precision. | Apply the existing cache timestamp tolerance to initial source comparison while retaining exact cursor size/time/file-identity validation. |
| Medium | Cold metadata scanning could read unbounded no-prompt files; warm scans repeated canonical path work and rewrote unchanged indexes. | Apply metadata byte budgets, retain bounded fallback entries, retry deferred summaries, validate inventory paths once per scan, reuse their metadata, and avoid unchanged index writes. |

## Error-log review

A read-only review of the preceding three days of macOS unified error/fault
logs for AgentDock found 40 records: 38 SwiftUI runtime warnings about
publishing changes during view updates, one network timeout (`-1001`), and one
empty record. No AgentDock/Codexer diagnostic crash reports or dedicated app
log directories were found in the inspected locations. These findings cover
available logs, not a guarantee that no other errors occurred.

A separate bounded read of the managed providers' local log databases found
three registered profiles with three distinct storage roots. At the initial
inspection, the preceding three days contained 140 errors and 119 warnings
(259 rows, below the 1,000-row per-profile inspection cap). Sampled recurring
engine errors reported missing custom tool-call outputs; another reported an
authentication-required transport closure. Warnings included connection,
timeout, MCP, and WebSocket handling. These are provider runtime records, not
evidence that AgentDock itself generated the failures. No transcript or
database repair was attempted, and no account names, tool-call IDs, or raw
message bodies are included here. Counts can grow while providers are active.

The warnings did not include a source stack, so their exact historical cause
cannot be established from those records. Initial view refresh now runs from
an asynchronous view task instead of synchronously inside `onAppear`. UI
acceptance must also check for fresh warnings; compilation does not prove the
historical issue resolved. A fresh unified-log check around the synthetic
native-window run found zero runtime-warning records for the test runner and
AgentDock; that bounded result does not establish the historical cause. The single timeout does not justify a retry loop or
provider-network changes without a reproducible failing request.

## Performance and maintainability

Cold Codex summaries now inspect at most 2 MiB per source and 16 MiB in total
with the default scanner configuration. Full transcript paging remains
available independently. Summaries deferred by the aggregate budget remain
eligible for subsequent scans. Complete oversized JSONL records obey the
summary line limit, and Claude usage reads stop at the inventoried file size
instead of chasing a growing file indefinitely.

Registry validation reuses canonical shortcut paths within each profile's
check, eliminating two repeated filesystem resolutions per loaded profile
without retaining a cross-operation path cache. Warm chat scans similarly
resolve inventory roots once and reuse validated source paths and metadata.
Transcript opening still checks nofollow, containment, file identity, and
mutation. Real filesystem regressions replace cached files and session roots
with symlinks, verify rejection, then verify recovery after restoration.
Chat grouping now makes one pass over filtered sessions. Official quota work
uses cancellation-linked workers so cancellation follows the owning refresh
without moving synchronous provider I/O onto the UI actor.
Existing bounded subprocesses, transcript pagination, capability gating, and
source ordering are retained. No large dependencies or framework migration
were introduced.

The model and provider parser files are still large. Future extraction should
follow measured change pressure and preserve their current safety contracts.
No evidence supports a wholesale rewrite or a claim that every possible
performance issue is eliminated.

## Validation and release boundary

Baseline `swift test` passed before changes. New regressions reproduced the
original storage/process attribution, lock, and subprocess defects where
feasible. After integration with current main, the full suite passed: 307
tests, 12 opt-in skips, and zero failures. The app-model and process-write
regressions completed without a signal crash.

An earlier run failed the 500-session warm inventory budget at 890 ms; it was
initially mislabeled as a transcript-page failure. The actual page took 1.16 ms.
After removing repeated path resolution, the focused check measured a 38 ms
warm scan and 1.02 ms first page. The final full-suite run measured 39 ms warm and
1.19 ms first page, within unchanged limits of 500 ms and 250 ms respectively.
Heavy machine load also caused timing variation in earlier runs. No threshold
was increased, and active provider applications were not stopped to improve
benchmark results.

The app-model harness uses temporary roots for standard provider data,
managed profiles, and indexes, so normal tests do not read active account
directories or overwrite their chat indexes. The synthetic native-window
harness passed and produced eight captures at regular and compact sizes in
both appearances. Inspection found and verified the light-mode transcript
contrast fix, persistent source identity, long-name layout, and compact
metadata adaptation.

The repository privacy audit, a separate redacted scan of all six new source
and document files, and `git diff --check` passed. After the final subprocess
fix, `./script/build_app.sh` and `./script/package_app.sh` both passed, including
bundle signature validation and DMG checksum verification. The local app,
ZIP, and DMG use ad-hoc signatures for review and are not notarized or
published.

The opt-in two-profile Codex lifecycle check passed: distinct processes,
persistence through restart, and preservation of the other temporary profile
and existing instances. A protected Claude rerun reproduced its earlier launch
failure and identified the cause: the environment override reached the signed
new process, but its browser files still used the default state directory.
Pairing the override with the matching Chromium user-data argument fixed the
failure. The two-profile Claude check then passed across close/restart with
all pre-existing instances preserved. Bounded open-file inspection found
84 and 82 files under each selected root, then 82 after restart, with zero
files under the default or sibling root in every inspection. The inspection
retries transient process-tree changes while revalidating the original main
process; it does not accept partial or failed tool output. Failed launches now reject reused PIDs
and leave unverified processes running. Retained failed-test instances were
closed only after revalidating their exact executable, signature, and recorded
launch time; successful test instances cleaned up through profile-scoped
lifecycle operations. Existing user instances stayed running; their account
files were not manually modified or migrated.

Provider contract inspection used locally installed, signature-verified Codex
26.901.51231 (build 8109) and Claude 1.46388.4. Provider updates can change those
contracts. Synthetic visual acceptance uses temporary records and isolated
preferences; it does not claim signed-in account acceptance. Native window
captures are required to assess glass/composited controls faithfully.

These checks validate the implementation before the repository release
pipeline. Merge, signed/notarized release assets, and public update-feed
publication are separate gates recorded by CI. The user's installed application
was not replaced or restarted. Signed-in multi-account authentication,
VoiceOver interaction, and long-running real-workload acceptance remain
separate evidence gates. Visual improvements are concrete, but an
"award-winning" claim requires user evaluation rather than a build result.
